# Settings and preferences

Read before changing appearance, language, or motion preferences.

- Browser-local appearance/locale/motion preferences are consolidated behind `useSettings()` (`app/composables/useSettings.ts`), backed by a single `wolfstar-settings` localStorage key (`AppSettings`: `colorMode`, `reduceMotion`, `selectedLocale`). Its `useLocalStorage` ref is created once in a detached `effectScope`, not in the first caller's own setup scope, so persistence survives that caller unmounting
- Prefer `useAppColorMode()`, `usePreferredLocale()`, and `useReduceMotion()` — thin wrappers around `useSettings()` — over reading/writing `wolfstar-settings` directly. `useAppColorMode()` also keeps `useColorMode().preference` in sync; `colorMode` supports `"system" | "light" | "dark" | "midnight"` (`midnight` is an experimental DaisyUI theme)
- Legacy keys (`wolfstar-theme`, `user-prefers-locale`, `user-prefers-reduced-motion`) migrate into `wolfstar-settings` once, only when `wolfstar-settings` has never been persisted — that check must run before the storage ref is created, since `useLocalStorage` writes defaults synchronously on first read
- `/profile` (and its `/account` alias) is **deprecated**: `nuxt.config.ts` answers both with a 301 to `/app`, and `app/pages/profile.vue` is only a shim that forwards a client-side navigation. Do not link to it or add anything to it. What it hosted moved: the server list is the picker of `/app` (`app/components/guild/Picker.vue`), and the browser-local preferences are `AppPreferences` (`app/components/app/Preferences.vue`), shown in the dialog `usePreferencesDialog().open()` opens
- Theme (cards with a preview, including the experimental midnight theme), the log tables' row density (`useLogDensity()`, Cozy or Compact) and language live in that preferences dialog, each on a page of its own; reduced motion is on its Accessibility page, and "Report a Bug" sits under the pages beside Sign out. The dialog is mounted once in `app/app.vue` and lazy-loaded on first open. It is reachable without signing in (the header's Settings button for guests) and, when signed in, from the header and the dashboard sidebar's account card; it is not a page and has no URL. Its "Report a Bug" section holds the feedback form
- Two dialogs share the open state of `usePreferencesDialog()`, told apart by its `variant`. The dashboard (account card, sidebar gear, bottom nav) calls `open()` and gets the two-pane dialog above. The header of every other page calls `openQuick()` and gets `AppPreferencesQuickDialog`: one compact page with the three base themes (dark, light, system; midnight shows only while it is the theme in use), the language, and reduced motion. It is `AppPreferences` with the `quick` prop, which leaves out the log row density and the clock format. Each dialog opens only for its own variant, and both are mounted lazily from `app/app.vue`
- `auth.redirects.guest` / `authenticated` and the guest-only route rules land on `/app`, which shows the server picker when no guild is selected
