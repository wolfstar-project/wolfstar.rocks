# Storage and caching

Read before changing Nitro storage mounts or cache drivers.

- On a Worker (`NITRO_PRESET=cloudflare_module`), `modules/cache.ts` puts `cache`, `fetch-cache` and the two rate limiters on Workers KV bindings through `shared/utils/storage/cloudflare-kv-fallback.ts`, which falls back to memory while the binding is not there (the prerender in Node, the plugins before the first request), and skew protection keeps a KV namespace of its own. KV has no compare-and-swap, so the rate limiters' read-modify-write cycles can race across isolates. See [cloudflare-workers](cloudflare-workers.md)
- The dashboard keeps the answers of its GET calls in the browser's localStorage (`app/utils/persisted-cache.ts`, keys `wolfstar-cache:<account id>:<asyncData key>`, a day at most): `usePersistedAsyncData()` is `useLazyAsyncData` that serves the stored answer at once on a reload or a return to a section and fetches again behind it, while a manual `refresh()` always fetches. The guild and its settings (`layouts/dashboard.vue`), the account's guilds (`useUser`), the three logs, the reports and the auto-moderation rules go through it. `app/plugins/persisted-cache.client.ts` empties the store when the account signs out or changes. Under test the store is off unless a spec calls `enablePersistedCacheInTests()`, since every browser-mode test file shares one localStorage
